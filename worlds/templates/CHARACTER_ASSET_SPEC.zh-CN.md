# 角色资产规范

[English](CHARACTER_ASSET_SPEC.md) | 简体中文

**角色资产和地图是一套美术。** 判断标准：**角色需要与地图的风格保持一致和统一。**

规范只约束：**有哪些角色**（性别 × 年龄段）、**有哪些动作帧**、**有哪些朝向**、**角色尺寸**，
外加锚点、配色分区、文件格式这三样交付要求。**体型、服装、鞋、发型一概不约束。**

---

## 1. 交付什么

**8 套身体 × 每套 76 帧，每套 1 张 PNG + 1 个 XML，外加一份清单。**

```
characters/
├── characters.json     # 清单，文件名固定
├── <body>.png          # 图集，每套身体一张
├── <body>.xml          # 帧描述（Starling / Kenney 格式）
└── <body>Portrait.png  # 可选：形象图，见第 7 节
```

---

## 2. 有哪些角色

**两个轴，八套身体。**


| 轴   | 取值                                     |
| --- | -------------------------------------- |
| 性别  | `male` / `female`                      |
| 年龄  | `child` / `young` / `middle` / `elder` |


**四档必须齐全**：某档没有身体，落在该档的角色就没有东西可画。若这套美术没有那么细的划分，
让相邻两档**共用**同一套，而不是留空。

**只有这两个轴。** 不要自己加阶层 / 职业轴。


| 档        | 年龄    |
| -------- | ----- |
| `child`  | 0–13  |
| `young`  | 14–37 |
| `middle` | 38–57 |
| `elder`  | 58+   |


**体型不作要求，但四档要在实际尺度下分得出来**——怎么分由你定。

---

## 3. 有哪些动作帧：11 个 pose，76 帧

**帧名由美术自己定**，写进清单的 `frames` 表——渲染器不认识任何具体帧名。右列是当前地图的写法，供参照。


| pose       | 当前帧名（`{dir}` = NE/SE/SW/NW）             | 帧数     | 身体在做什么             |
| ---------- | --------------------------------------- | ------ | ------------------ |
| `walk`     | `walk{dir}0..3`                         | 16     | 行走循环               |
| `idle`     | `idle{dir}`                             | 4      | 站立，重心自然            |
| `down`     | `fallFaceUp{dir}` / `fallFaceDown{dir}` | 8      | 倒地不起               |
| `attack`   | `swing{dir}0..2`                        | 12     | 起手→挥出→收势，**徒手挥臂**  |
| `interact` | `operate{dir}0..1`                      | 8      | 操作眼前之物，双手在身前忙碌     |
| `talk`     | `talk{dir}Closed` / `talk{dir}Open`     | 8      | 面向对方说话，一手抬起示意      |
| `shove`    | `push{dir}`                             | 4      | 双手前推 / 擒拿，**不是击打** |
| `duck`     | `duck{dir}`                             | 4      | 屈膝伏低，重心下压          |
| `hold`     | `take{dir}`                             | 4      | 俯身取物 / 抱住          |
| `show`     | `give{dir}`                             | 4      | 把东西向前递出，手臂伸直       |
| `hurt`     | `hit{dir}`                              | 4      | 上身后仰、重心失衡的受击瞬间     |
|            |                                         | **76** |                    |


一个 pose 给多帧即成动画，给一帧即静止姿势，两者都合法。

**红线：一套身体会被任意多个角色、任意多个故事复用。一个 pose 会被多个行为复用，所以任何身体以及身体 pose 都应该尽量通用，不应绑定特定行为。**

## 4. 方向

四向按**屏幕走向**命名：`NE`（右上，背对镜头） `SE`（右下，面向镜头） `SW`（左下，面向镜头）
`NW`（左上，背对镜头）。等距 2:1，与地图网格一致。

**为什么定向动作也要四个方向**：引擎在播放任何 pose **之前**会先转身，所以每个动作都需要带着完整朝向
进来。目的是为了在播放 pose 的时候更加符合人类行为的认知常识，比如 `talk` 的时候就应该两人面对面。

**而镜像只能把人转向左右，转不过身**：只画朝东的话，朝北时会画成正脸——目标在四向上大致均匀，
也就是约一半的定向动作会背朝目标却面朝镜头。

`duck` / `hurt` / `down` 没有朝向要求，不过为了统一，所以建议都给 4 个朝向。

## 5. 画布与锚点

- **一套资产内所有帧尺寸统一**；具体尺寸由美术自己定，缩放由清单的 `scale` 声明。
- **锚点：帧底边中点 = 双脚中点 = 等距格中心。** 所有帧共用同一锚点，切 pose 时不得位移跳变
——**这是最常见的交付缺陷**。`down` 同样以「身体重心投影点」对齐该锚点，不要按站立脚位摆。
- **帧内四周留余量**，挥击 / 倒地时肢体不得被画布裁切。

**角色在地图中的屏幕高度是刻意放大的（约 3×），不建议修正为比例更小的尺寸（当然如果地图足够大可以考虑调整）。** 按现有地图的真实尺度，如果按照合适的比例缩放，一个人可能就只有十几像素，一个头 2px，四个朝向退化成同一坨色块。以现有的地图尺寸，**推荐的 `scale` 范围是 0.22–0.36，** 现有地图两套都取 `0.28`。至于取多少由制作人自行决定。

## 6. 配色（硬约束，违反会导致染色崩坏）

**身份色不是画上去的**，是引擎在绘制时按**像素颜色分区**重染上去的：


| 判定顺序 | 条件             | 归属                  | 处理     |
| ---- | -------------- | ------------------- | ------ |
| 1    | 明度 V ≤ 0.08    | 描边                  | 原样保留   |
| 2    | 色相 H ≤ 60°（暖区） | 皮肤 / 棕发 / 皮革 / 中性灰白 | 原样保留   |
| 3    | 其余             | **服装**              | 重染为身份色 |


由此四条：

1. **服装主体必须是冷色或中性色**（蓝、青、绿、紫、灰、白、黑）。**绝不能把主要衣物画成土黄、
  赭石、朱红、橙、驼色**，那会落进暖区被判成皮肤，该角色将**完全失去身份色**，导致在地图上与他人
   无法区分。⚠️ 这条对古装尤其危险：唐代服饰的直觉配色几乎整片压在暖区，**画唐装时请主动把直觉
   里的赭红换成同明度的青、绿、靛、藕、缃灰。**
2. **服装的中明度基准画在 V = 0.70。** 折痕与高光围绕这个值上下浮动——引擎按 0.70 归一化后重染，
  染出的中间调正好落在身份色上，而明暗关系被完整保留。**画暗了，身份色就出不来。**
3. **皮肤落在暖区**（H ≤ 60°），全部肤色正常画即可。**头发**：棕色系 ✅ / 中性黑（R=G=B 的深灰
  黑）✅ / 中性白 · 灰白 ✅ / **带蓝调 · 紫调的黑发 ❌**（会被判成服装并重染）。
4. **不要为不同角色准备不同配色**，每套身体只画**一版**即可，个体差异由引擎染色产生。

> 单靠颜色数值无法区分部位。同一个色值（#bf7958）在不同角色上既可能是皮肤也可能是头发，两者的色相和饱和度完全重叠。这不是阈值没调好的问题，而是规则本身的局限，所以目前只能把整个暖色区当成一体处理。

## 7. 清单文件 `characters.json`

上面所有决定写进这一份文件，渲染器只读它：

```jsonc
{
  "scale": 0.28,         // 帧内像素 → 屏幕像素（取值理由见第 5 节）
  "walk_fps": 8,         // 行走循环帧率
  "bodies": {            // 性别 → 年龄档 → 图集 key（四档必须齐全，可共用）
    "male":   {"child": "…ChildMale", "young": "…", "middle": "…", "elder": "…"},
    "female": {"child": "…", "young": "…", "middle": "…", "elder": "…"}
  },
  "atlases": {           // 图集 key → 文件，路径相对地图目录
    "…ChildMale": {"image": "characters/x.png", "atlas": "characters/x.xml",
                   "portrait": "characters/xPortrait.png"}   // portrait 可选
  },
  "frames": {            // pose → 帧名。三种写法都合法：
    "idle":  {"NE": "idleNE", "SE": "idleSE", "SW": "idleSW", "NW": "idleNW"},   // 四向静帧
    "walk":  {"NE": ["walkNE0", "…"], "SE": […], "SW": […], "NW": […]},          // 四向动画
    "duck":  "duckSE"                                                            // 单向（引擎镜像）
  }
}
```

PNG 32 位带 alpha、无预乘；XML 的 SubTexture 坐标不得越出 PNG 边界。

`down` 只取一个帧名，而美术可能同时画了仰卧与俯卧：按**朝向连续性**挑——朝北（背对镜头）死的取
俯卧、朝南（面向镜头）死的取仰卧，这样倒下的人保持他生前给观众看的那一面。

`_comment` 字段只是用来记这套美术的定位与已知偏差，渲染器会忽略它。

### 形象图 `portrait`（可选）

角色的认知体检浮层按形象图尺寸放大显示身体，图集里的帧（身体约 190px 高）放大后会糊，所以每套身体可以
另给一张高清形象图。**形象图不必是 idle 帧本身，但必须和它统一**：

- **同一个人**：面部、发型、体型、年龄感一致。
- **同一身衣服**：款式、配色一致；配色规则与第 6 节相同，引擎用同一套规则给形象图染身份色。
- **同一种站法**：和这套身体的 `idle` SE 帧一样，面朝镜头偏右、自然站立。浮层的引线按这个站姿落在头、
  心口、手、脚上，换了朝向或姿势就会落空。
- **同一种画风**，和地图、图集一致。
- **透明底** PNG（带 alpha），裁到人物边界即可；人物建议 ≥ 1000px 高（孩子 ≥ 850px）。

校验器把形象图和 idle SE 帧都裁到人物边界再比两项：**轮廓重合 ≥ 0.94**（换姿势、换朝向会被拒），
**大块明暗分布接近**（换了人会被拒）。面部细节和画风机器判断不了，在地图工作台的「Cast」页签里把形象图
和 idle 帧并排对照，需制作人自行确认。缺形象图的身体会默认使用 idleSE 帧，但是会出现糊掉的效果。

## 8. 验收

先跑校验器（它会连角色一起查）：

```bash
.venv/bin/python -c "from worlds.template_check import check_template; print(check_template('地图目录名') or 'OK')"
```

它自动查：`bodies` 四档齐全、`atlases` 文件都在、11 个 pose 都有、每个帧名在图集里真的存在。

**剩下的靠眼睛看**——打开**地图工作台**的「Cast」Tab，它把第 3 节那张表整个渲染出来，验证项可以有以下几点：

- **这些角色的风格与地图一致，统一。**
- **所有帧锚点一致**：开「Stack」，逐帧叠放时双脚中点不漂移。
- 四档年龄在实际尺度下**分得出来。**
- 挥击、倒地帧的肢体**未被画布裁切**：开「Canvas」看边框。
- 单向 pose 均朝**东**；镜像后角色左右无不对称固定特征（看「mirrored」角标）。
- 角色**没有遮住脚下建筑**：切「In game」按真实尺度看。

配色两条（第 6 节的 V≈0.70 与色相区）界面上看不了，仍要回画图软件验证。

### 与本规范的已知偏差

重画前先看这里，别重复踩。**以规范为准，不以现有地图为准。**


| 项                       | 规范要求     | changan_iso | metro              |
| ----------------------- | -------- | ----------- | ------------------ |
| 服装中明度                   | V = 0.70 | 0.42–0.56   | **0.11–0.33**      |
| `young` / `middle` 分得出来 | 必须       | **分不出来**    | **分不出来**           |
| `elder` 分得出来            | 必须       | 矮 5% + 背驼   | **与青年等高**，只剩背驼一个信号 |
| 东西向                     | 给四向即视为分画 | 实为**像素级镜像** | 同左                 |


- **服装明度**两套都偏暗，metro 尤甚：身份色染出来只剩意图的两成到五成，相近颜色的角色更难
分辨。这是当前最该修的一条。
- **`young` / `middle` 两套都分不出来**（壮年躯干反而比青年窄 7–13%）。体型本身不作要求，
分不出来才是问题。
- **东西向两套都是镜像**，代价是 76 帧里约一半不含新增信息；对古装还多一层——交领在其中一侧
必然是左衽。游戏尺度下领口只有几像素，当前接受。
- **遗留问题**：人物移动的动作帧还有很明显的问题。不过现在不影响功能，也不影响叙事，这个问题可以先不用关注。
