# 可观测性与审查

[English](observability.md) | 简体中文

两件工具服务于同一个目的：让叙事质量**可见、可评、可调**。**Trace** 记录每一次 LLM 调用，**Audit** 对跑完的世界做离线质量评审。Web 界面的入口在开发者工具 `#/dev`，需要先打开开发者工具，见 [开发](development.zh-CN.md#开发者工具)。

## LLM 调用追踪（Trace）

Asamana 把角色认知拆成一次次独立的 LLM 调用，所以 trace 就是角色思考过程的完整记录：每次调用的 prompt 与响应、token、耗时、所属认知阶段，以及每一步的总耗时。叙事出了问题，从这里能定位到是哪个角色、哪一步、哪个阶段出的错。

- **开关**：配置的 `observability.enabled`，默认开启（测试配置关闭）。
- **落盘**：`data/traces/<world_id>/`，建世界一个文件，之后每个运行步一个文件（JSONL）。
- **查看**：`#/dev` → **Trace**，可按步、阶段、角色分组，点开任意调用看完整的 prompt 与响应。

## 世界质量审查（Audit）

用 LLM 评审一个跑完的世界叙事质量。核心原则：

1. **事后、只读**：只读取已有的 trace，不重跑仿真，评审的是实际发生过的叙事。
2. **导演视角**：从 7 个维度打分，分为基础与提升两层，即基础层看故事有没有讲错，提升层看故事有没有讲得平淡。
3. **按取证粒度分 scope**：不同问题要在不同的范围里才看得出来，即角色失忆要跨步看，无效社交要跨角色看，叙事是否收敛要看全局。所以审查分成 5 个 scope，每个只评它看得到的维度。
4. **扣分制**：见下一节，这是整套审查机制的核心理念。
5. **如实报告证据**：叙事质量（世界总分）与工程忠实度（`fidelity_score`）分开计，一个世界可以毫无臆造却很无聊；某些维度证据不全时，报告会标出取证覆盖率，覆盖率不同的两次审查不能直接比较。

### 为什么一切都是扣分

每个维度从 **100** 分开始，只会被扣分，不会加分。判官拿到的是一份列明各类错误的评判标准，如失忆、凭空捏造事实、原地打转、最俗套的剧情走向等等，命中一条扣一次分。这样设计有三个理由：

1. **判官找具体错误很准，给整体打分则不然**。模型擅长发现并处理明确、客观、明显的问题。比如“这和他第 12 步的做法矛盾吗？”，对于这个问题，答案可以非常客观、简单、直接、明显；“这个故事给多少分？”，这类问题就很主观，没有统一的评判标准。
2. **分数衡量的是下限，不是上限**。高分并不表示这个世界好，只表示没有明显出错：没有自相矛盾，没有凭空捏造，没有人忘记自己刚做过的事等等。所以审查的目的是把常识性、逻辑性、明显的问题指出来并解决掉，自然而然下限会提高，叙事质量也会提升。
3. **不评上限，把有意思的部分留给涌现**。下限之上，判官不发表主观意见，即一个世界不会因为“不够精彩”被扣分，只会因为明显地、可证明地糟糕而被扣分。要评上限，首先得定义什么是好，而对不同的人来说，“好”的叙事又是见仁见智，所以不应该按判官的标准去评判叙事“好”与“不好”。而且这个项目存在的意义，正是看看会涌现出什么内容。

由此有两个推论，在报告里都能看到：

- **“看不出”是空值，不是零分**。判官没有依据时弃权，这个维度退出加权，不会把分数拉低。
- **判分依据只列错误，不给标准答案**。判官被明确要求：不能因为输出和它自己会写的不一样而扣分。

### 维度与 scope

| 维度 | 看什么 | 权重 |
|---|---|---|
| 人设与世界观一致性 | 言行是否偏离性格、身份与世界观常识 | 20% |
| 因果逻辑连贯性 | 行动、情绪、需求能否溯因，不凭空、不失忆、不臆造 | 20% |
| 行动有效性 | 是否空转、重复；社交是否真正改变了世界或关系 | 20% |
| 叙事收敛度 | 是否朝核心冲突、主题与长期目标推进 | 15% |
| 戏剧性弧线 | 情绪、压力与冲突是否有起伏张弛 | 15% |
| 涌现趣味 | 是否有信息差带来的误会、反转与博弈 | 5% |
| 角色成长 | 经历重大变故后，角色是否发生实质变化 | 5% |

| scope | 审查范围 | 看什么 |
|---|---|---|
| `mams` | 全体角色 × 全部步数 | 整体叙事：是否收敛、有无弧线与涌现、行动是否有效、是否符合世界观 |
| `sams` | 单个角色 × 全部步数 | 这个角色是否人设一致、因果连贯、行动有效，有没有成长与起伏 |
| `init` | 世界初始化 | 开局设定：人设与关系是否自洽，历史时间线是否合理 |
| `mass` | 全体角色 × 单步 | 同一时刻角色之间互动：谁知道什么、反应落在谁身上、同处的行动是否互相矛盾 |
| `sass` | 单个角色 × 单步 | 每次思考是否忠于它拿到的输入，不凭空添事实（只计入忠实度分）；调用次数最多、最贵 |

日常关注 `mams`、`sams`、`init` 即可。

### 运行

在 `#/dev` → **Audit** 里发起，或用命令行（需要 key，judge 模型由配置的 `llm.judge` 指定）：

```bash
python -m tuning audit <world-id>                     # 全部 scope
python -m tuning audit <world-id> --scope mams,sams   # 只跑某些 scope
```

只跑部分 scope 不会覆盖其他 scope 的已有结果，世界总分始终由全部结果重新汇总。结果保存在 `data/traces/<world_id>/audit/`。

### 调整判分标准

每个维度在每个 scope 下的判分依据写在 `tuning/audit_criteria.yaml`，改完重跑即可，不需要改代码。维度定义与权重在 `tuning/audit_metrics.py`。
